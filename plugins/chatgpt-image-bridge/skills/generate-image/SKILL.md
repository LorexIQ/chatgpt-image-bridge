# generate-image

В Claude Code нет своего генератора изображений. Этот скилл рисует картинки на подписке ChatGPT пользователя, поэтому API-ключ OpenAI не нужен. Режимов два:

- **web** (по умолчанию) — скрипт открывает chatgpt.com в отдельном профиле Chrome, отправляет промпт в чат и скачивает картинку, которую нарисовал ChatGPT. Картинку можно дорабатывать следующими сообщениями в том же чате.
- **codex** — скрипт вызывает встроенный инструмент `image_generation` из Codex CLI через `codex exec`.

Режим выбирает пользователь. Ты всегда вызываешь одну точку входа — `image-bridge.mjs`, а она передаёт вызов скрипту нужного режима.

## Когда использовать

Вызывай скрипт, когда пользователю нужна сгенерированная картинка. Например:

- «Сгенерируй hero-картинку для…»
- «Сделай мокап / логотип / аватар / иллюстрацию…»
- «Покажи, как мог бы выглядеть X»
- «Перерисуй эту картинку в другом стиле» (с `--image`)
- «Сделай фон темнее» — правка только что созданной картинки (см. «Доработка картинки»)
- Дизайн-скилл работает по схеме «сначала картинка, потом код» и просит изображение

**Не** вызывай для:

- диаграмм, графиков, схем, SVG и UI-разметки — их точнее сделать кодом (mermaid, SVG, HTML);
- мелких программных PNG (однотонные плейсхолдеры, пиксели) — хватит пары строк Python;
- попиксельной правки существующего файла.

## Как вызывать

Запускай через инструмент **Bash** (на Windows это Git Bash, не PowerShell):

```bash
node ${CLAUDE_SKILL_DIR}/bin/image-bridge.mjs "<промпт>" <абсолютный-путь-к-результату.png> [--size WxH] [--image <файл>]... [--chat <адрес>]
```

- **Только через `image-bridge.mjs`.** Не вызывай `codex-image` и `chatgpt-image.mjs` напрямую: так не учтётся режим, который выбрал пользователь.
- **Промпт** — плотный и режиссёрский: композиция, свет, камера и объектив, настроение, стиль. Короткий промпт даёт шаблонный результат.
- **Путь к результату** — абсолютный. Для черновиков подойдёт временная папка, для ассетов, которые нужно сохранить, — папка в проекте, например `design/`. Папка должна существовать.
- **`--size WxH`** — необязателен. Передавай, только если пользователь назвал размер или макет требует определённых пропорций. Формат `1536x1024`. В режиме codex это размер для инструмента картинок, в режиме web — только подсказка о пропорциях: в веб-интерфейсе нет параметра размера, фактический размер выбирает ChatGPT.
- **`--image <файл>`** (можно несколько раз) — исходная картинка для редактирования или референс по стилю и композиции. В промпте опиши, как её использовать («сохрани композицию, поменяй палитру на…»).
- **`--chat <адрес>`** — только в режиме web: продолжить разговор, в котором уже есть картинка (см. «Доработка картинки»). В режиме codex вызов с `--chat` завершится кодом 2.
- Генерация занимает 30–90 секунд в режиме web и несколько минут в режиме codex. Ставь таймаут Bash на **максимум, 600000 мс**, или запускай в фоне и дождись завершения. Если вызов прерван, скрипт сам останавливает codex или браузер и убирает временные файлы.
- **Один вызов за раз.** В режиме web все вызовы работают с одним профилем браузера и встают в очередь, в режиме codex параллельные вызовы только быстрее тратят лимиты. Несколько картинок генерируй последовательно.

## Режим

- **По умолчанию не передавай `--via`**: скрипт сам берёт режим, который настроил пользователь.
- `--via codex` или `--via web` добавляй, только если пользователь **в этом запросе** явно попросил конкретный способ («эту сгенерируй через codex»). Это разовый выбор, настройку он не меняет.
- Если пользователь просит переключиться насовсем («генерируй через браузер», «переключись на codex», «дальше рисуй через codex»), выполни и сообщи ему результат:

  ```bash
  node ${CLAUDE_SKILL_DIR}/bin/image-bridge.mjs mode web     # или mode codex
  ```

  Режим сохраняется в `~/.chatgpt-image/config.json` (остальные ключи файла не меняются). Если в stderr есть предупреждение — профиль браузера не настроен или режим переопределён переменной `CHATGPT_IMAGE_MODE`, — передай его пользователю.
- Узнать текущий режим — `node ${CLAUDE_SKILL_DIR}/bin/image-bridge.mjs mode`. Ответ вида `web (по умолчанию)`, `codex (config.json)` или `web (CHATGPT_IMAGE_MODE)`: в скобках — откуда взят режим.
- Порядок выбора: `--via` → переменная окружения `CHATGPT_IMAGE_MODE` → `"mode"` в `config.json` → `web`.
- Пользователь может переключать режим и сам — командой `/chatgpt-image-bridge:image-mode [codex|web]`.
- Не меняй режим сам, чтобы обойти ошибку. Если режим не работает (нет codex, нет входа), скажи об этом пользователю и предложи другой режим.

## Результат

| Код | Что значит | Что делать |
| --- | --- | --- |
| 0 | Картинка готова | stdout: первой строкой абсолютный путь (на Windows в виде `C:/...`, его можно открыть через `Read`). В режиме web второй строкой `chat: <адрес разговора>` — её может не быть, если адрес определить не удалось. Режим web исправляет расширение под фактический формат, поэтому бери путь из вывода |
| 1 | Картинки нет. codex: codex завершился с ошибкой или инструмент не сохранил картинку — в stderr хвост лога и путь к полному логу. web: ChatGPT ответил текстом (отказ, лимит, вопрос), не успел за таймаут или страница повела себя неожиданно — в stderr причина (для текстового ответа сам текст) и папка со скриншотом и HTML страницы | Разберись по stderr и расскажи пользователю. Отказ и лимит не повторяй |
| 2 | Ошибка аргументов, неверный режим (в `--via`, `CHATGPT_IMAGE_MODE` или `config.json` — источник назван в сообщении) или `--chat` в режиме codex | Исправь вызов; неверную настройку режима покажи пользователю |
| 3 | Только web: нужно действие пользователя — нет входа в ChatGPT, проверка браузера (Cloudflare) или открыто окно входа | См. «Режим web: вход» |
| 127 | Не хватает программы. codex: нет codex CLI или bash. web: нет Node.js 22+ или Chrome/Edge | Попроси пользователя установить недостающее |

После успешного вызова открой картинку через `Read` и оцени результат, прежде чем писать код или отвечать.

## Режим web

### Вход и проверка браузера (код 3)

Если stderr говорит, что открыто окно входа, попроси пользователя закрыть его и повтори вызов. В остальных случаях запусти в фоне (`run_in_background`):

```bash
node ${CLAUDE_SKILL_DIR}/bin/image-bridge.mjs login
```

Сообщения скрипта называют эту команду `chatgpt-image login` — запускай её так, как показано выше. Откроется обычное видимое окно браузера с профилем скрипта. Попроси пользователя войти в ChatGPT или пройти проверку в этом окне, а потом закрыть окно — команда завершится сама. После этого повтори генерацию. **Никогда не вводи логин, пароль или коды за пользователя** и не пытайся пройти проверку сам.

### Доработка картинки

После каждой удачной генерации в режиме web запоминай адрес из строки `chat:`. Если пользователь хочет что-то поменять в этой картинке, не генерируй её заново, а продолжи тот же разговор:

```bash
node ${CLAUDE_SKILL_DIR}/bin/image-bridge.mjs "сделай фон темнее, кота оставь как есть" /abs/cat-v2.png --chat https://chatgpt.com/g/g-p-…/c/…
```

- В промпте опиши **только изменения**. Прошлая картинка и промпт уже в разговоре, скрипт сам просит ChatGPT нарисовать новую версию с этими правками.
- **Не передавай повторно `--image`** с референсами, которые уже были приложены в этом разговоре: ChatGPT их видит. `--image` нужен только для нового референса.
- Сохраняй новую версию в новый файл, чтобы не потерять прошлую, если правка не понравится.
- Для новой, не связанной картинки начинай новый разговор — вызывай без `--chat`.

Продолжение сохраняет контекст, поэтому картинка меняется точечно и остаётся согласованной с прошлой версией, а ChatGPT не нужно заново разбирать весь промпт и референсы.

### Как это устроено

- Скрипт запускает системный Chrome (или Edge) с отдельным профилем `~/.chatgpt-image/profile`. Окно открывается за краем экрана: пользователь его не видит, трогать его не нужно. Браузер закрывается после каждого вызова, в том числе при ошибке и прерывании. Если прошлый вызов был убит и оставил браузер, следующий вызов его закроет.
- Генерации идут в проект ChatGPT, адрес которого задан в `~/.chatgpt-image/config.json` как `projectUrl`, а без него — в новый обычный чат. Временные чаты не подходят: в них ChatGPT картинки не рисует.
- Скрипт вводит промпт с короткой инструкцией на английском (нарисовать картинку инструментом генерации, не задавать уточняющих вопросов), прикладывает референсы, ждёт готовую картинку и скачивает её со страницы.
- Всё, что зависит от устройства chatgpt.com, собрано в `lib/chatgpt.mjs`. Если ChatGPT поменяет интерфейс, вызов завершится ошибкой с кодом 1, а чинить придётся только этот файл.

### Что нужно пользователю

- Node.js 22 или новее и Google Chrome или Microsoft Edge (путь к другому браузеру на Chromium — в `CHATGPT_IMAGE_BROWSER`).
- Подписка ChatGPT и один раз выполненный вход: `node ${CLAUDE_SKILL_DIR}/bin/image-bridge.mjs login`.
- Если chatgpt.com открывается только через прокси — расширение прокси, установленное в окне входа (в этом профиле, а не в основном браузере).
- По желанию — проект в ChatGPT для генераций и его адрес в `~/.chatgpt-image/config.json`: `{ "projectUrl": "https://chatgpt.com/g/g-p-…/project" }`. Так картинки не засоряют основную историю чатов.

## Режим codex

- Продолжения разговора нет: `--chat` не работает. Чтобы поправить картинку, вызови генерацию заново с прошлым результатом в `--image` и опиши в промпте, что поменять.
- `login` в этом режиме ничего не запускает, а только напоминает: вход выполняется командой `codex login` в терминале пользователя.

### Как это устроено

Скрипт запускает:

```
codex exec <флаги облегчения> --skip-git-repo-check -s workspace-write -C <временная-папка> "<промпт>" [-i <картинка>]...
```

с явным требованием вызвать инструмент `image_generation`, а не рисовать PNG на Python.

**Облегчённый запуск.** Всё, что не нужно для картинки, выключается: плагины, MCP-серверы из конфига codex, все скиллы, apps, browser и computer use, мультиагентность, shell, web search, память, `AGENTS.md`, хуки и команда `notify`. Фичи выключаются, только если установленная версия codex их знает. Настройки песочницы берутся из конфига codex.

**Модель и effort.** Картинку рисует сам инструмент, модель codex только передаёт ему промпт, поэтому скрипт фиксирует дешёвую модель `gpt-5.6-sol` и effort `low`, чтобы не тратить лимиты. Переопределять их переменными `CODEX_IMAGE_MODEL` и `CODEX_IMAGE_EFFORT` стоит, только если пользователь сам об этом попросил.

**Проверка источника.** Инструмент `image_generation` сохраняет результат в `$CODEX_HOME/generated_images/<session id>/`. Скрипт берёт session id из лога codex и копирует в нужное место только эту картинку. PNG, созданный любым другим способом, не принимается, и вызов завершается ошибкой. Codex не работает с итоговым путём, поэтому отказы песочницы и путаница путей Windows/POSIX исключены, а старый файл перезаписывается только когда новая картинка действительно есть.

### Что нужно пользователю

- Установленный `codex` CLI: `npm install -g @openai/codex` (на macOS также `brew install codex`).
- `codex login status` показывает «Logged in using ChatGPT» — нужна подписка ChatGPT.
- Включена фича `image_generation` — по умолчанию включена (`codex features list | grep image_generation`).
- bash: на macOS и Linux есть, на Windows — Git Bash (им пользуется Claude Code) или WSL.

Если скрипт пишет «codex CLI не найден», попроси пользователя установить codex и выполнить `codex login` — или предложи переключиться на режим web.

## Стоимость

- **Оплаты OpenAI API нет.** Режим codex расходует лимиты Codex в плане ChatGPT — те же, что и обычная работа в Codex. Режим web расходует лимиты генерации картинок — те же, что в приложении ChatGPT.
- Лимиты ограничены, поэтому не трать их на пробные картинки без нужды.
- Если ChatGPT ответил текстом про лимит или отказ, код 1 несёт этот текст. Передай его пользователю и не повторяй вызов в цикле.
